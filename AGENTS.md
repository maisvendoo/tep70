## Project Overview

Данный проект - дополнение к [Russian Railway Simulator](https://github.com/maisvendoo/RRS.git).

## Architecture

- cfg/trains - конфиги поездов
- cfg/vehicles - конфиги единиц подвижного состава
- docs/ - документация
- data/models - 3D-модели
- data/animations - конфиги анимаций
- data/sounds - звуки и конфиги звуков
- scripts/ - инсталляция проекта после сборки в симулятор и деплой дополнения для распространения

## Commands

Последовательность сборки:

- Убедится, что заданы системные переменные RRS_DEV_ROOT и RRS_DIR
- Выйти в каталог уровнем выше. Если существует каталог содержащий в имени build перейти в него. Если таких каталогов несколько, отдать предпочтение каталогу содержащему в имени release
- cmake -DCMAKE_BUILD_TYPE=Release ../sources (или любая дргугая папка, содержащая исходники)
- Win: mingw32-make; Linux,macOS: make

## Rules

- Перед началом работы уточнить путь к исходному коду симулятора RRS
- Ничего не делать с кодом или конфигами без утверждения плана действий!
- Не править SDK симулятора без разрешения! Всегда подробно и обоснованно объяснять какие правки SDK требуются и чем это обосновано!
- План реализации разбивать на слайсы - этапы, не ломающие функциональность проекта! Недопустимы слайсы приводящие к невозможности сборки! 
- Реализация каждого слайса должна сопровождаться коммитом и пуш в удаленный репозиторий.
- Не переключать без разрешения текущую ветку проекта! Не ходить без разрешения по другим тэгам!
- Не откатывать без разрешения правки, внесенные разработчиком!
- ЗАПРЕШЕНО СРОЖАЙШЕ редактировать файлы gltf так как они являются результатом экспорта из Blender! Разрешается читать и анализировать данные файлы.
- ЛЮБОЕ изменение файлов проекта ЗАПРЕЩАЕТСЯ без четкого разрешения данного разработчиком.
- Реализация любой задачи ДОЛЖНА начинаться с тщательного изучения тех аспектов архитектуры игры, которые связаны с задачей. План реализации, представляемый на утверждение должен содержать пояснение, объясняющее плпниаруемые действия на основе SDK игры и её исходного кода. КАЖДАЯ задача должна быть уточнена с учетом текущего состояния кода симулятора, предлагаемых разработчиком примеров!
